91-94% of the CSS on every page is never used — ~158 KB each time CSS-WASTE · high

Measured against the production build with the DevTools Coverage panel: every page downloads 172 KB of CSS and uses between 10 and 15 KB of it. Dashboard uses 10 KB, Laboratory 15 KB, Queue 11 KB. The remaining ~158 KB is downloaded, parsed and thrown away on every single page, for every user. That is the signature of Tailwind's purge not reaching the files it should — the whole utility set is shipping instead of the classes actually used.

This is the one number here that is absolute: it comes from the built bundle, it is a separate file from the JavaScript, and minification does not distort it.

The heap does not quite return to where it started MEM-DRIFT · medium

Each module was loaded, left, and garbage-collected before the heap was read. On the page the heap sits at 20-25 MB; after leaving it falls back to about 9.4 MB — so nothing large is being held. But the floor drifts upward across the eight modules: 9,426 → 9,446 → 9,454 → 9,514 → 9,561 → 9,550 KB, about 124 KB not reclaimed over eight navigations.

This is not a leak in the usual sense; a leak would be megabytes. It matters because of who uses this app: a counter that keeps one browser tab open all day, moving between modules hundreds of times. One reading is noise — the drift is the signal, and it needs a longer run to confirm.

PARTLY WITHDRAWN — The app shell repaints for things that happen inside the module DASH-SHELL · low

36 actions caused App, Navigation or NavLink to re-render. The worst is 195× in a single action. The sidebar is not part of this module and has no reason to repaint when a table pages or a filter changes — this is one memoisation gap in src/App.jsx, and every module pays for it.

Retracted 10 August — measuring error. This count came from e2e/profiler.mjs, which counted every fiber whose actualDuration was above zero. React leaves that value on a fiber after its last render, so a component that bailed out of a commit still carried the cost of whenever it did render, and the walk counted it again on every commit. The tool now compares actualStartTime against the end of the previous commit and reports self time with children subtracted. Re-measured on Queue — the module with the largest number here — three keystrokes produce App ×16 and Navigation ×16, and no NavLink renders at all: the memoisation in src/App.jsx (commit 15c804d) is working. The shell does still re-render once per commit, which is worth its own look, but it is not the hundreds this row claimed.

Precise JavaScript coverage of the SHIPPED bundle is still not measured COV-JSGAP · low

Two attempts produced numbers that could not be true. The first summed V8's nested ranges and reported more bytes used than loaded — impossible, and the giveaway. That is fixed. The second ran against the production build and reported 0% waste for every module, which is an artefact of minification: the whole file collapses into a few large functions, and V8 marks a function used the moment it runs once.

So the JS figures in this report are from the dev server and are comparative only. Getting an honest absolute needs source maps applied to the built bundle. Recorded here rather than left as a number nobody should trust.
