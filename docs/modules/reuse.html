What to extract, and what it buys

Six extractions, front and back, each measured from the duplication scan rather than proposed from taste. Every one names the files, the line counts, and the bug that the duplication is waiting to cause.

The test CLAUDE.md rule 9 gives: if you can describe what you built without naming a module, it belongs in a shared lib. Each heading below passes that test. The rule also warns against the opposite mistake — one module with an imagined future need is speculation — so every proposal here points at a second real caller that exists today.

Backend 1The admission guard — written 13 times in one file

Thirteen copies of the same four decisions highest value

// backend/src/controllers/inpatientController.js — this block, 13 times
const { admissionId } = body;
if (!admissionId)
  return res.status(400).json({ success: false, error: "admissionId required" });
const admissionBelongsToOrg = await ownedAdmission(orgId, admissionId);
if (!admissionBelongsToOrg) {
  return res.status(404).json({ success: false, error: "Admission not found" });
}

Counted in the file: 13 admissionId required, 18 ownedAdmission() calls, 19 Admission not found. The numbers do not match each other — which is the finding. Somewhere in those eighteen call sites, the id is checked for ownership without first being checked for existence, or the reverse.

What it should be — one guard that returns the admission or ends the request:

// backend/src/lib/ipdGuards.js
export async function requireOwnedAdmission(req, res, admissionId) {
  if (!admissionId) {
    res.status(400).json({ success: false, error: 'admissionId is required' })
    return null
  }
  const admission = await db.admission.findFirst({
    where: { id: admissionId, organizationId: getOrgId(req) },
    select: { id: true, patientId: true, status: true, bedId: true },
  })
  if (!admission) {
    res.status(404).json({ success: false, error: 'Admission not found' })
    return null
  }
  return admission
}

// every call site becomes two lines
const admission = await requireOwnedAdmission(req, res, body.admissionId)
if (!admission) return

What it buys. Roughly 90 lines removed. But the real gain is security: this is CLAUDE.md rule 4, and rule 4 is enforced only by the code — the database does not check tenancy. Thirteen hand-written copies of a tenant guard means thirteen chances for one to be written slightly differently, and the one that is wrong is invisible until another hospital reads a patient's admission. One function means one place to be right, one place to test, and one place to change when the check needs to grow (a discharged admission should probably not accept new charges — today that would be thirteen edits).

It also returns the row, so most call sites stop issuing a second query to fetch what the guard already had.

Two screens show the same patient's balance from two copies of the same defaulting and the same markup. Note the shape of the default: records.billing || { totalBilled: 0, … }. If one copy later starts using ?? and the other keeps ||, a genuine balance of 0 renders differently on the two screens — and 0 being falsy is a bug this repository has already paid for.

What it should be: <PatientBillingSummary records={records} /> in src/components/common/.

What it buys. 50 lines gone, and — more importantly — one answer to "what does this patient owe". Two components computing money independently is how two screens come to disagree in front of a patient at the counter.

The shared location already exists; a module is simply carrying its own copy. const iframe = document.createElement(…) is not domain logic — it is plumbing, and plumbing in a module file is plumbing that will be missed.

Frontend 4The numeric form field, ten times over

Three consecutive copies inside one file rule 2

src/components/laboratory/LaboratoryModule.jsx
  :1955-1969 ⟷ :1974-1988 ⟷ :1993-2007     ← three copies, back to back

<Input type="number" {...field} value={field.value ?? ''}
  onChange={(e) => field.onChange(e.target.value === '' ? undefined : parseFloat(e.target.value))} />

Counted across the app: 5 in Laboratory, 3 in Pharmacy, 2 in Billing — ten hand-written copies of the same three decisions (empty string becomes undefined not NaN; value ?? '' so React does not warn about an uncontrolled input; parseFloat not parseInt).

What it should be: <NumberField control={form.control} name="price" label="Price (₹)" />

What it buys. Around 70 lines, and every numeric field in the application starts agreeing about what an empty box means. It also becomes the one place to add what none of the ten copies do today: refuse a negative price, cap decimals at two, and reject e and + which type="number" accepts and parseFloat silently mangles.

The benefit that is not a line count

Deleting ~230 lines is the smallest part of this. What each extraction actually buys is that a fix lands once. Every duplicate in the table above is a bug that will be fixed in one copy and left in the other — and nobody will know, because the fixed copy is the one that was being looked at. That is not a prediction: it is what happened to the lab report HTML, to the age calculation, to the patient-name builder and to the date-range helper, each of which drifted apart across modules before a shared lib existed.

It also changes what a review can catch. Reading a diff cannot find a second copy in a file the reviewer has not opened — but it can very easily catch a change to a shared function, because everything that depends on it is one search away.

What NOT to extract

The scan also flags twenty-four blocks repeated inside a single file, and several of them should stay. Three near-identical <FormField> blocks for referenceMin, referenceMax and criticalLow are worth extracting because the logic inside them is identical. A status badge coloured per module is not — CLAUDE.md rule 9 is explicit that "colour the Laboratory status badge" stays in Laboratory. One module with an imagined future need is speculation, and a wrong abstraction costs more than a second copy.
