A disabled module's route is never registered, so React Router falls through to <Navigate to={homePathFor(role)}> and the dashboard appears. Twelve of the sixteen module URLs behave that way.

The obvious worry turned out to be unfounded, and was checked rather than assumed. modulesEnabled starts as {} while settings are in flight, so it looked as though a disabled module would mount, fire all its API calls and only then vanish — a flash of a screen the user should not have, paid for with real server work. Correct behaviour. Recorded because the opposite was expected and the expectation was wrong.

What this costs the audit open

Any module that is switched off cannot be walked — the harness measures the dashboard instead and reports it under the module's name. That is what produced the three identical rows, and it means the remaining modules cannot be audited until they are enabled in Settings → Modules.

It also puts a question against the earlier runs: Pharmacy and Queue returned genuine data — 196,744 drugs, real queue rows, working category filters — which is only possible if they were enabled at the time. Their findings stand on that evidence. Their coverage numbers may not, and are marked accordingly rather than quietly kept.

node e2e/route-check.mjs now reports where every module URL actually lands, so this cannot go unnoticed again.

One command runs all of it

node e2e/verify-all.mjs --quick     # ~10s, data checks only, no browser
node e2e/verify-all.mjs             # everything, every module
node e2e/verify-all.mjs --module billing
node e2e/verify-all.mjs --base https://…       # against a deployed environment

It never repairs anything. Every probe either reads, or writes only to rows it creates and deletes in a finally — the pharmacy one rolls its whole transaction back. The exit code is 1 when anything critical is found, so it can gate a deploy.

239 of the 481 are the harness, not the app. The per-category budgets are button 60, icon 40, card 12, table row 15, checkbox 15, filter option 8. Laboratory found 246 controls, so its 53 cards and 52 icon buttons were never reached — that single module is 179 of the 481.

Two of the low scores are findings, not gaps. Pre-Triage sits at 22% and Death Certificates at 40% because their search endpoint returns 400: the table empties, so there are no rows left to click. The coverage number is measuring a broken screen, which is the correct thing for it to do.

Getting to 100% means removing the budgets, which takes a module from 4–8 minutes to roughly 30–40. That is a deliberate trade, not an oversight, and it has not been made yet.
